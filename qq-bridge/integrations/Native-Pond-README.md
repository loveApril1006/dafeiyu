# 机器人内的原版 B站鱼塘

用户要求保留 dsh-bili-pond 的完整界面与能力，只把部署与入口移到机器人后台。
现在使用上游 `bili-pond-upstream/client.js`、`index.js` 和原版数据、调度、提示词、MCP、
转写实现；没有向 DSH desktop profile 注册该插件或增加其设置页。
上游提交仍是 923d884698bb7b3b9de8a651de970c801bf10d0d，源码未修改，MIT/NOTICE均保留。

## 入口与功能

原来的机器人后台 `http://127.0.0.1:3100/#bilibili` → B站鱼塘。
配色跟随机器人控制台的主题变量，支持浅色/深色与自定义强调色即时同步；
iframe内切换主题不重载页面，不丢失当前标签和设置草稿。独立打开时使用相同的保存主题。
构建时从public/console.html提取默认主题，robot-theme.css将原版颜色映射到这些变量；
不修改上游源码，升级后重建界面即可保留这层配色适配。
原版界面在同源iframe中展示，保留头像、等级、统计、视频封面墙、筛选、记忆、日记、
设置、评论模式（关闭/圈地自萌/普通评论/楼中楼）、私信、自动运行、评论区守护、
自动转写、运行日志、报告、账号登录与模型线路选择。

自动阅读、评论、私信、评论守护与自动转写的开关都保持关闭；所有功能由用户自行配置。
原版私信收件人限制、内容阅读要求、配额、去重与圈地规则均沿用原实现。
“一键升级”不再执行 `dsh plugin add`，以免重新向DSH注册界面；
独立部署源码的升级要通过机器人部署流程完成。

管理员QQ私聊保留 `#搜B站`、`#看B站`、`#B站评论`，并支持 `#刷B站`、`#B站状态`、
`#B站日报`、`#B站记忆`、`#B站日记`。刷一轮/报告/记忆/日记读取完整鱼塘的数据；
早期的指定BV字幕总结仍由基础适配器处理。

## 适配代码与数据

- `companion/bilibili-native.mjs`：在生活服务内给原版提供最小宿主接口，所有设置只写本机。
- `integrations/bili-standalone/browser-entry.js`：用React18挂载原版页面，为同源API带控制台令牌。
- `build-ui.mjs`：将React及原版页面一起构建为独立HTML；重建时运行 `node build-ui.mjs`。
- `dsh-cli.mjs`：通过现有Electron模型引擎执行headless CLI，多行提示词保持单个argv，不经过shell。
- `engine.json`：本机引擎位置，不含密钥，不应直接搬到别的电脑。
- `/api/bili-pond/*`：机器人3100控制台先执行原有鉴权/Origin/agent隔离，再代理给17867生活服务。
- `companion/bili-native-data/`：原版配置、账号、报告、封面缓存、判重、记忆、日记、会话和转写缓存。

数据目录使用现有ACL保护。早期基础版的账号/历史/报告做一次性导入，旧数据保留。
主Python环境通过 `.venv` junction复用已安装的独立运行环境；ASR使用独立 `.venv-asr`，
faster-whisper、yt-dlp、av<17和small模型已安装，CPU int8加载成功。
headless模型仍用机器人原有线路和本机凭据存储，不向前端或模型公开B站cookie。

`pack.py`已排除两份B站个人数据目录和 `bili_credential.json`。本次没有更新现有换机ZIP，
下次打包需专门补齐该集成及可搬动的运行环境，不能直接复制本机venv/junction代替安装。
