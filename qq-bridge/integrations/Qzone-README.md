# 小鸽子QQ空间：自主写稿、配图与发布

入口：机器人后台 → **QQ空间**，沿用后台配色。总开关、自主写稿、自动配图、自动发布和定时运行分别控制，初始全部关闭。只查看页面或保存关闭状态的配置不会调用模型、访问QQ或启动Python。

## 使用

在空间页填写主题和配图风格。写稿复用机器人当前聊天模型与人格，使用无工具预设，不读取群聊、私聊或长期记忆。模型一次返回正文和配图描述，不具有QQ、文件或电脑工具。

自动配图复用“娱乐与创作 → 画图工作台”的提供方、模型与密钥；先在那里配置并开启生图功能。普通聊天模型不能代替生图服务。图文任务先检查生图配置，缺失时不调用写稿模型。每条只生成一张PNG/JPG/WebP、最多8MB；配图失败不改发纯文字。

打开总开关和自主写稿后，可以“只生成预览”；这始终只生成草稿，即使自动发布已打开。打开自动发布后，“按设置运行一次”会写稿、配图并直接发布，无需逐条确认。打开定时运行后按间隔执行，第一次在保存设置后的下一个间隔。单独关闭自动发布则定时只写草稿。

默认每6小时尝试一次，写稿每日2次、发布每日2次，两次发布至少间隔4小时；自动运行时段为北京时间09:00～22:00，默认好友可见。所有数值均可在后台调整；发布权限使用QQ实际参数：1公开、4好友、64仅自己。生图还受画图功能独立额度限制。模型失败、取消及已经提交的发布尝试也计入各自额度。关闭总开关会取消等待和在途任务，保留配置与稿件。

## 发布与数据

复用本机SnowLuma当前QQ登录，任务开始时检查登录与空间Cookie是否可取；发布仍可能因为登录过期或平台响应而失败。Cookie只在一次性Python进程内存中使用，不保存、不回显、不传给模型。此模块不自行扫码、不抓取浏览器、不操作微信。

图片上传与发布底层使用 [Eganchiyu/qzone-sdk](https://github.com/Eganchiyu/qzone-sdk)，固定提交 `2282b8bc50c185eb6f8f7a39a3c8c6a517484d77`，MIT；源码和许可证保留在 `integrations/qzone-sdk-upstream`。未执行上游安装或登录脚本。通过受限HTTP适配器调用一次图片上传和一次发布，限制目标域名、响应大小与超时，拒绝重定向，不自动重试。上游文档的可见范围描述与其直接传参实现不一致，本模块使用QQ接口参数值，不使用文档中的3=好友映射。

私有目录 `companion/qzone-data` 使用ACL收紧；原子保存配置、每日预算和稿件状态。保留最近30条，空间配图上限64MB；页面按需预览一张，不同时加载整库。全模块只运行一个任务，定时器在关闭时停止，不设后台空轮询。原有管理员私聊 `#说说 正文` 和桌宠 `发说说：正文` 文字发布入口保留。

提交前先保存 `publishing` 状态；必须获得说说ID才标记成功。超时、中断、重启或未知响应标为 `uncertain`，这些稿件不能自动或手动重发；应先去实际空间核对。图片上传成功但发布失败时平台可能保留上传素材，本模块不会冒充删除成功或再次提交。

## 二次开发与验证

- `src/qzone/core.js`：开关、频率、额度、稿件与单次发布状态机。
- `src/qzone/service.js`：后台路由、无工具模型调用及已有生图功能适配。
- `src/qzone/transport.js` / `companion/qzone-autopost.py`：一次性进程、QQ登录、图片上传与发布。
- `public/qzone.html`：主题继承、配置、预览与记录。
- `npm run test:qzone`、`npm run test:qzone-ui`、`python scripts/test-qzone-worker.py`：状态机、真实桥接认证、浏览器、真实SDK与假HTTP。所有模型、QQ和生图外发均使用替身，不能据此宣称实际账号发布成功。

管理接口复用控制台认证、Host/Origin边界并拒绝agent访问：`/api/qzone/status`、`config`、`run`、`publish`、`stop`、`image/<稿件ID>`。配置需带当前revision，模型输出不能更改开关、触发管理接口或授权发布。
