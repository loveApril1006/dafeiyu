# 功能联动、资源开关与空间检查

本轮已把修改加载到当前安装。QQ、聊天引擎和音色读取接口正常，主配置文件的 SHA-256 与重启前一致；已核对的功能开关也保持原值。桌宠当前未启动，桌宠相关开关显示未连接，不自动启动桌宠。

## 已完成的修改

后台左侧新增「资源与开关」，集中管理 QQ 主动联系、QQ／桌宠语音、屏幕陪伴、黑话学习与研究、角色记忆、音乐、跑团、画图、表情包、微信，以及 QQ空间写稿、配图、定时发布和工作日报。长期记忆、上下文、视觉路由和搜索插件沿用原来的插件开关。B站鱼塘、直播、抖音等模块保留详细设置入口。

集中页面直接修改各模块的原配置，只在进入、手动刷新和保存后读取状态，没有另建调度器。切换单项时保留其他设置；同一个页面的保存串行执行，各模块原有的版本冲突检查继续生效。桌宠配置读取共享正在进行的请求，短暂缓存 2 秒，不向页面返回引擎凭据。

修复了两个实际的开关问题：

- QQ 语音开关的局部保存原来可能覆盖整个语音配置，现在保留语音目录、音量、限额及其他工具开关。
- 微信手动发送原来没有先检查图片／文件开关，参数错误也会留下「发送结果不确定」的记录。现在发送前校验，电脑版接口只开放已经支持的文字收发，无效输入不会触发模型、传输或发送记录。

## token、CPU 与内存

角色记忆默认召回最多 3 条；无匹配时只带 1 条最近偏好，数量设为 0 可关闭召回。角色状态投影默认上限 1800 字符，可在「角色状态与偏好记忆」调整到 600～6000 字符。日记只投影有限片段，超出预算先移除记忆、日记和日期，再缩短展示字段；原始记录保留。工作陪伴上下文使用独立上限，不能把角色状态字符上限理解为整次模型输入上限。

作息配置只在 SQLite 配置内容变化时重新校验，仍会立即看到另一个进程保存的设置；时间格式器和记忆关键词缓存都有容量上限。工具名扫描先过滤文件类型，避免把视频、模型等二进制资源读取成文本。

桌宠设置窗口改为上一次状态请求结束后再安排下一次请求。窗口隐藏时暂停，关闭时清理定时器，慢请求不会叠加。现有主后台及嵌入页面的隐藏暂停、请求合并和重试退避也通过了回归检查。

同一组合成样例（保存 200 条记忆、读取 100 次快照；没有模型请求）：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 本地快照总耗时 | 285.05 ms | 92.47 ms |
| 无关话题的角色状态投影 | 2090 字符 | 650 字符 |
| 数据库保存的记忆 | 200 条 | 200 条 |

这是合成样例中的本地耗时和字符数，不能当成实际总 token、费用或整机内存下降比例。真实开销还取决于模型、人设长度、会话历史、图片和主动任务频率。已启用的主动联系、语音等功能没有为省资源被擅自关闭。

语音功能开关停止后续合成；已启动的模型后端可能仍驻留内存。需要回收模型内存时，通过本机管理窗口停止相应后端。

后台主页面从 **309372 字节（约 302 KiB）缩小到 86666 字节（约 85 KiB）**，减少约 72%。样式独立到 `public/console/console.css`，交互代码按职责拆为 5 个文件：

| 文件 | 主要内容 | 大小 |

| persona-models.js | 人格与模型设置 | 50.9 KiB |

提取时校验了拼接前后的脚本字节完全一致。服务端仍按原顺序一次返回完整的经典脚本，保持跨文件函数提升和初始化行为；不引入前端框架、eval 或额外模型请求。静态资源使用 ETag，未变化时返回 304；只有固定的公开 JS／CSS 地址免令牌，账号数据和管理 API 的鉴权仍保留。

真实浏览器的 23 项控制台检查、桌面／手机布局和跨页面主题检查通过。静态资源另测了字节与顺序一致、缓存更新、304、HEAD、固定路径、Host 限制和 API 仍需鉴权。更新已加载到当前后台，功能开关保持原值。
