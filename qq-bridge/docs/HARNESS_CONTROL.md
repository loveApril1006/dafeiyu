# QQ 与 Harness 控制

后台侧栏「Harness 控制」管理总开关、管理员交办、自主任务、结果通知、额度和项目权限。默认总开关关闭、无授权项目、自主任务关闭。代码安装后重启原 Harness 引擎，加载 `qq-harness-isolated` 预设；缺少预设时拒绝执行，不回退为完整权限的 standard。当前机器人连接哪个 Harness 实例，任务就创建在哪个实例的真实项目和会话中。

## 项目授权与隔离

先创建一个独立项目目录，再在后台填写代号、名称和绝对路径。新项目默认只读，自主使用需要另勾选。当前第一版只提供一个项目文件工具，支持列目录、分页读取、创建/覆盖文本文件、唯一文本局部替换。可处理代码、网页、Markdown、JSON、CSV、SVG等文本文件。没有任意命令、删除、联网、发布、插件管理、子代理工具；不能声称运行过测试。

任务预设隐藏全部继承工具，并有执行期白名单，猜工具名也不能绕过。工具身份来自实际执行会话，不接受模型提供的会话或项目路径；服务端通过随机能力凭据绑定会话、工作目录、截止时间和当前授权。每次文件操作都重新检查总开关、来源、管理员、项目身份及写权限。

目录越界、绝对文件路径、Windows ADS、设备名、符号链接、目录联接、硬链接被拒绝。机器人、引擎、模型、系统和凭据目录不能作为远程项目；需要修改运行中的程序时先操作独立副本，再人工检查应用。项目内隐藏目录、状态、日志、依赖和凭据命名文件也不提供给任务。文本会检查明显凭据及已知会话令牌；这不是对任意内容的完整秘密识别，因此只授权确实可交给模型的项目。

覆盖已有文件需先读取并提供SHA256，发生并发修改时拒绝覆盖；大文件仅允许局部替换。覆盖前保存备份，写入采用同目录临时文件替换。路径检查不能防御本机同权限恶意程序在检查间隙修改文件系统；此隔离针对模型/QQ工具请求，不是操作系统容器。

## QQ 操作

只有后台设置的管理员本人私聊能交办。群聊（包括管理员在群里的消息）、普通好友和其他群的模型令牌均不能借用。入口要求实际来信，模型不能伪造管理员来源。

- `Harness 项目`：查看可选项目。
- `Harness 新建 work | 生成一个网页`：在代号work的项目创建任务。
- `让Harness帮我：生成一个网页`：只有一个项目时可省略代号。
- `Harness 进度`、`Harness 结果`、`Harness 任务`：查看状态和结果，不调用模型。
- `Harness 暂停`、`Harness 取消`：收回文件权限、清除待处理队列并请求取消当前回合，保留已完成修改和聊天。
- `Harness 继续 补充要求`：同一会话继续，计入新的执行回合；正在运行时先暂停并保留进度。
- `Harness 进入工作`：本次桥接运行期间，后续自然语言作为当前工作任务的补充；`Harness 退出工作`恢复普通聊天。关闭控制或重启桥接也退出工作对话。

同一个任务继续原来的Harness会话。标题标为【QQ交办】或【自主任务】；目录里的真实文件可以在同一实例查看。角色卡只决定交付表达，不能授予权限。

## 自主任务与预算

总开关、自主开关、项目自主权限同时开启后，二代仿真中管理员当前私聊的角色可在已有聊天或自主唤醒机会中，通过 `qq_harness_task` 提交具体目标。使用既有聊天模型决定目标，没有额外的循环规划器。其他人的会话没有此入口的执行权限；模型提交始终按自主来源检查，不能指定管理员来源或路径。关闭自主开关会从MCP工具清单移除入口，文件权限仍由后端即时复查。

一次只执行一个任务。管理员交办可暂停自主任务后优先执行。自主目标当天去重，有每日任务数、最长时长、最多文件调用数；token预算在步骤结束时检查，当前模型请求可能超过预算，单次模型输出另限制为2048 token。自主完成不会自动派生新的任务。任务结束、暂停、关权限、换管理员、重启后旧能力凭据无效；停止未确认时阻止开启新的任务。

完成通知只直接发送实际最终结果，不调用第二个总结模型，不自动重发失败通知。任务状态、摘要和最多24条阶段日志保存在 `state/harness-control/jobs.json`（最多30项）；任务覆盖备份每项最多8MB、60个文件，随最近30项任务保留。Harness自身保存完整聊天和工具记录。桥接重启会撤销旧能力，不自动重放任务或通知；管理员需明确继续。

权限只由已鉴权的后台修改，代理请求、跨站来源、无效Host、过期配置版本被拒绝。公开打包模板只导出开关与额度；项目绝对路径、项目授权、任务、文件内容、备份和能力凭据不打包。
